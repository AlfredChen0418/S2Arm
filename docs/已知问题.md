# 已知问题

本文件供外部贡献者参考，按区域分组。每条包含：编号（KI-xxx）、问题概述、代码位置、影响说明和建议修法。需要真机或游戏读数才能安全改动的条目会在建议修法中注明。

## 着色器

### KI-002 印章和库容器在收尾表完成前落盘

- **位置：** `graphics/tools/direct/dsh/batch/Build.cs:267-273`
- **影响：** 批文件写入结果在两张收尾表完成前即落盘，进程中断时文件可能处于不一致状态。
- **建议修法：** 收尾表全部完成后再落盘，或写到临时路径后 rename。

### KI-003 Mach-O 加载命令 size 字段不检查下界，size ≤ 0 时下标不前进

- **位置：** `graphics/tools/direct/dsh/batch/Build.cs:162-186`
- **影响：** 解析 Mach-O 加载命令时不校验 size > 0，畸形二进制可导致解析死循环。
- **建议修法：** 读取 size 后若 size ≤ 0 则报错终止解析。

### KI-004 c0 常量缓冲 0x200 段只记 16 字节，宿主侧拷 12 字节，两侧大小不一致

- **位置：** `graphics/tools/direct/compiler/DirectComputeC0Reads.cs:81`
- **影响：** c0 的 0x200 段被记录为 16 字节，宿主只拷 12 字节；安卓路径超 12 字节时失败。
- **建议修法：** 明确两侧约定大小，统一后在单测中覆盖边界值。

### KI-005 着色器段布局歧义时固定按一种方向处理

- **位置：** `translator/shader_split.py:478-481`
- **影响：** 两种布局都与特征匹配时始终选其中一种，可能导致部分着色器段识别错误。
- **建议修法：** 歧义时打黄字并记录命中款，积累后决定是否补充启发规则。

### KI-006 同一文件两种指令方向混排时少数方向跟着多数走

- **位置：** `graphics/tools/shbake/nxsh_extract.py:270-292`
- **影响：** 一个文件内背靠背出现两种指令方向时按全局票数决定，少数方向可能被错误翻译。
- **建议修法：** 对每段独立判断方向，不按全局票数。

### KI-007 合并遍的双源混合未标记第二源

- **位置：** `graphics/nvn/gfx/nvn/nvn_pso_skey.h:25-26`
- **影响：** 管线状态键生成时合并遍双源混合被当成无第二源，可能导致着色器复用错误。
- **建议修法：** 在管线键中正确标记双源混合标志位。

### KI-008 着色器接口预算包含已删除的 CullDistance 分量

- **位置：** `compat/tree/src/Ryujinx.Graphics.Shader/CodeGen/Spirv/Declarations.cs:519-521`
- **影响：** 预算仍含已删除的 CullDistance 1 个分量，预算略偏高；这是本仓修改的代码而非上游原文。
- **建议修法：** 从预算中减去已删除的分量。

### KI-009 precise:: 替换在四处独立实现，NaN 口径分散

- **位置：** `graphics/tools/direct/dsh/batch/Build.cs:678,830; graphics/tools/spirv_msl.py:36,292`
- **影响：** fast::min/max/clamp 改为 precise:: 在四处各自实现，修改任一处而不同步其余三处时 NaN 行为会分开。
- **建议修法：** 提取成一份共享函数，调用方各留入口。

### KI-010 可读瓦片 _bf 变体编译失败时不打错误日志

- **位置：** `graphics/tools/direct/dsh/batch/Build.cs:454-458`
- **影响：** _bf 变体编译失败直接返回，不打红字；同文件 _ft 变体失败会打红。
- **建议修法：** 失败时打红字，与 _ft 保持一致。

### KI-011 批文件 rename 成功后索引追加失败，索引与实际文件不一致

- **位置：** `graphics/nvn/gfx/nvn/pso_archive.h:240-250`
- **影响：** 批文件 rename 已成功但索引追加失败时，批文件已存在而索引未记录，后续查找找不到。
- **建议修法：** 追加索引失败时删除已 rename 的批文件，保持一致性。

### KI-012 预编代码副本取不走时留到进程结束

- **位置：** `graphics/nvn/host/dsh_miss.inc:113-133`
- **影响：** 首遇时预分配代码副本，若未被取走则持续占用直到进程退出，着色器数量多时累积可观。
- **建议修法：** 设上限或在确认不再需要时主动释放副本。

### KI-013 深度池改写后不再追加 alpha 丢弃，Alpha 比较恒为 Always

- **位置：** `graphics/tools/direct/dsh/batch/Build.cs:824-826`
- **影响：** 池改写加早测深度后 alpha 丢弃逻辑不再添加，影响依赖 alpha 测试的着色器。
- **建议修法：** 加早测深度后检查并补回 alpha 丢弃路径。

### KI-014 首遇着色器按自报 nctl 大小拷贝，nctl 在 0x100–0x707 范围时可能越出堆块

- **位置：** `graphics/nvn/host/dsh_miss.inc:75-78,158,235`
- **影响：** 首遇时按 nctl 大小拷贝，当 0x100 ≤ nctl < 0x708 时从副本 +0x704 偏移读代码长，可能越出当前堆块边界。改前须确认是否存在更短但能通过阶段判定的在用着色器。
- **建议修法：** 对 nctl 大小做上下界检查，不足 0x708 时拒绝或按安全大小分配。

## 渲染

### KI-015 池表缺省已启用，每个池首次写入时仍读到 0 并丢失

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:8839-8840,8853-8858`
- **影响：** 池常驻缺省已开，首次提交命令时读取池数据得 0 并提交，导致首帧池数据丢失。改前须有一款会走池表的游戏，记录首帧及后续几帧的读数。
- **建议修法：** 首次碰到池时先驻留再提交；不改回缺省关闭，不改为一上来驻留所有池。

### KI-016 档位梯子、设置和事件周期写入不在同一处，重启后状态不一致

- **位置：** `runtime/src/host_main.c:252; runtime/src/qladder_host.c:36-44; runtime/src/fps.c:399-400; ios/settings.m:101-106; graphics/nvn/gfx/nvn/nvn2_codec.c:98`
- **影响：** 档位初始写入、设置保存和事件周期分散在多处，立刻重启未清 g_hold，导致设置页与实际档位不一致，且事件周期不随档位切换。改前须有一款可降档的游戏，验证重启后状态。
- **建议修法：** 收成已有的一处写入；不改梯子缺省，不加第四套档位。

### KI-017 越过预留的虚拟池映射仍返回成功

- **位置：** `graphics/nvn/gfx/nvn/hle_nvn.c:3931,3975-3984`
- **影响：** vsh_cover 在必须覆盖的范围越过预留时返回 0（成功），调用方无法感知失败，读写映射到错误地址。改前须有一款会打出相关日志的游戏，确认当前返回成功。
- **建议修法：** 越过预留时返回失败；不删 :3975 的早退，不将减半退回改为整池放弃。

### KI-018 子遍渲染区域未覆盖完整帧缓冲（实测 0 次命中，待确认）

- **位置：** `graphics/nvn/gfx/vk/hle_vk.m:1615,1637,1680,1820`
- **影响：** renderArea 小于帧缓冲时按子区域绘制；多重采样整张存储后按区域解析，覆盖关系可能不完整。此前实测 0 次命中，待确认是否有能复现的场景。
- **建议修法：** 在有命中读数之前维持当前区域绘制方案。

### KI-019 纹理类型探针仅计数，运行时不修正绑定（实测 0 次命中）

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:9212-9225,9417,9447`
- **影响：** 离线翻译遇到缺类型时按 2D 翻译；运行时探针只累计计数，不修正实际绑定。此前实测 0 次命中，改绑定须有计数 > 0 的读数。
- **建议修法：** 探针保留；待有计数 > 0 的读数后再决定是否修正绑定。

### KI-020 会话复位时只释放着色器程序，g_jobs 任务列表未摘除

- **位置：** `graphics/metal/gal_prog.m:726,818,1312-1314`
- **影响：** 会话复位只释放已编译程序，g_jobs 里对应任务条目未摘除，后续会话可能引用已释放的程序槽。
- **建议修法：** 复位时同步从 g_jobs 摘除对应条目。

### KI-021 同尺寸同矩形拷贝将目的存储一并放宽，不检查目的是否为交换链

- **位置：** `graphics/nvn/widen_glue.inc:389-400`
- **影响：** 判断放宽拷贝时不区分目的是否为交换链，可能将不应放宽的目的做了放宽处理。
- **建议修法：** 放宽判断中检查目的是否为交换链，交换链目的不放宽。

### KI-022 放宽拷贝的矩形两端各自取整，宽度可能差 1 像素

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:13224,13505-13512,13554-13557`
- **影响：** 源边和源边加宽各自用 lround 取整，宽度为两者相减；两个小数向相反方向进位时，宽度会少 1 或多 1，放宽拷贝的矩形与上屏盖满情况可能差 1 像素。纵轴、剪刀 y 和触点已改走出图比例，不在此条内。
- **建议修法：** 只保留一套换算。该改动会改变当前差 1 像素的拷贝结果；改前须有一款放宽拷贝较多的游戏，记录改前的矩形像素和上屏是否盖满。

### KI-023 上屏细节量横向最多 16 张，随后额外整高派发一遍

- **位置：** `graphics/nvn/widen_glue.inc:153-184`
- **影响：** 细节计算横向上限 16 张，第一遍宽×32，接着再派发一遍全高，实际工作量多于必要值。
- **建议修法：** 根据实际分辨率动态计算所需细节量，去掉固定上限和多余的全高遍。

### KI-024 命令回放主循环 OP_JUMP 无步数上限

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:14073-14096`
- **影响：** 回放主循环处理 OP_JUMP 时没有步数上限，构造畸形命令流可能导致无限循环。
- **建议修法：** 添加跳转步数计数器，超过合理上限时终止回放并报错。

### KI-025 编译并发数在旧系统版本上固定为 2

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:7987-7991`
- **影响：** maximumConcurrentCompilationTaskCount 的设置包在较新系统判断内，旧系统上并发数维持 2，无法利用更多核心。
- **建议修法：** 将并发数设置移出版本判断，或为旧系统设置合理的缺省值。

### KI-026 返回栈或调用深度超限时前瞻改为无条件派发

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:10392-10394,10438`
- **影响：** 返回栈深于 16 或调用深于 64 时，前瞻策略改为「都要」，可能引入不必要的派发开销。
- **建议修法：** 超限时打黄字；评估是否应截断而非改策略。

### KI-027 窗口切段中间数组满时静默跳出，不打错误日志

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:8940,8976`
- **影响：** 切段的中间数组满时直接 break，最终表超 8192 才打红字；中间状态丢失但无日志。
- **建议修法：** 数组满时立即打红字。

### KI-028 四边形条带转三角形时 CPU 个数取偶，间接绘制 GPU 个数未同步

- **位置：** `graphics/nvn/gfx/nvn/hle_nvn.c:1913-1919`
- **影响：** 转换时 CPU 侧顶点个数取偶，但间接绘制路径的 GPU 个数保持原样，两者不一致可能产生渲染错误。
- **建议修法：** 间接绘制路径与 CPU 侧取偶逻辑保持一致。

### KI-029 几何绘制在 gmem_count_draw 前返回，池计数只增不改驻留

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:12712,12723`
- **影响：** 几何绘制路径提前返回，gmem_count_draw 未执行；计数只增加，不触发池驻留决策。
- **建议修法：** 确保几何绘制路径也执行 gmem_count_draw，或在提前返回前完成计数。

### KI-030 前瞻换画布时整表标脏，qb[160] 填充后不派发

- **位置：** `graphics/nvn/gfx/nvn/nvn_mtl.m:3836-3838,10148-10188`
- **影响：** 前瞻结束时整表标脏；qb[160] 队列填充后不自动派发，存在无谓的标脏开销。
- **建议修法：** 只标实际更改的条目；qb[160] 添加派发触发或移除。

### KI-031 返回栈只保留 16 个槽，深度 17–62 时成环扫描均不命中

- **位置：** `graphics/nvn/gfx/nvn/nvn_xqueue.inc:91-95`
- **影响：** 返回栈最多 16 个入口，深度 17 到 62 时扫描一圈均不命中，跳转目标丢失。
- **建议修法：** 增大返回栈上限，或超限时报错而非静默丢失。

### KI-032 差不足 1 像素铺满只在苹果通用出图路径实现，另两份截断

- **位置：** `graphics/metal/gal_present.m:191-194`
- **影响：** 苹果通用出图路径有「差不到 1 像素就铺满」逻辑，另外两份出图路径直接截断，上屏结果不一致。
- **建议修法：** 在另外两份出图路径补充相同的铺满判断。

### KI-033 持久着色器缓存写入不检查返回值即 rename

- **位置：** `graphics/metal/gal_prog.m:754-760`
- **影响：** .msl/.rec 缓存文件写入不检查 IO 返回值，写入中途失败时 rename 仍将不完整文件换成正式名称。
- **建议修法：** 写入后检查所有 IO 返回值，失败时删除临时文件，不执行 rename。

## 原生层

### KI-034 满屏采样线程在画面未放宽时仍每秒请求判断一帧（按设计维持）

- **位置：** `runtime/src/qprompt_host.c:6,24-31,77`
- **影响：** 满屏采样设计上每秒请求一帧判断，画面未放宽时请求不产生实际输出但仍有开销；线程 detach 后无法主动回收。按设计维持此行为。
- **建议修法：** 按设计维持；如需优化，评估是否可在不需要采样时暂停请求。

### KI-035 渲染分辨率跟随窗口像素（按设计维持）

- **位置：** `runtime/src/widen.c:228-235; macos/front_mac.m:434-436`
- **影响：** 拖动窗口时每次偶数尺寸均触发重建；玩家钉定 16:9 或通过环境变量指定屏幕尺寸时不跟随。按设计维持。
- **建议修法：** 按设计维持；拖动中频繁重建的性能问题参见 KI-040（P2-108）。

### KI-036 退回 16:9 的标志和自检 done 会话间不清零

- **位置：** `runtime/src/widen.c:227,642-657; runtime/src/qprompt_host.c:42`
- **影响：** 退回 16:9 标志跨会话不清；尺寸缓存清零后下一局可能按真屏重算；跟屏和再次热切仍被挡住。
- **建议修法：** 会话复位时清 done 标志和退回标志。

### KI-037 qp_reset 无调用方；采样线程换局时不拆除

- **位置：** `runtime/src/qprompt.c:37; runtime/src/qprompt_host.c:77`
- **影响：** s2a_qp_reset 在生产代码中无调用方；采样线程换局时不做拆除，线程可能操作旧会话资源。
- **建议修法：** 换局时调用 qp_reset，或将采样线程纳入会话生命周期管理。

### KI-038 缺省线程掩码按 3 位设置，硬件核数可到 8

- **位置：** `runtime/src/thread.c:230,919,2328-2329`
- **影响：** 调度开关关闭时主线程和核号 -2 的缺省掩码为 7（3 位），第 4–8 核缺省不参与调度。
- **建议修法：** 缺省掩码按实际核数动态设置，或改为全核掩码。

### KI-039 帧率数据跟随槽位固定 64 个，满后跳过不打红字

- **位置：** `runtime/src/cpatch.c:19,107-108`
- **影响：** g_fd[64] 满了只打「整份不开」后跳过当前行，不打红字。
- **建议修法：** 满时打红字；评估 64 个上限是否足够。

### KI-040 每次布局事件都跟屏，拖动时每次偶数尺寸触发一次重建

- **位置：** `macos/front_mac.m:427-436; runtime/src/widen.c:222-234`
- **影响：** 窗口布局变化时无防抖，拖动期间偶数尺寸触发重建，换屏代数持续累加，影响拖动性能。
- **建议修法：** 添加防抖（如延迟 200ms 内无变化再重建），减少拖动中的重建次数。

### KI-041 非 Mac 平台取不到物理内存足迹时不写回峰值表

- **位置：** `tools/mem_admit.sh:203-212; tools/phys_footprint.py:14-18`
- **影响：** libproc 取足迹失败时静默跳过，峰值表不更新，基于峰值的内存决策在这些平台上失效。
- **建议修法：** 取足迹失败时打黄字，峰值表填入已知下界或标记无效。

### KI-042 切程序时重读帧率表，但环境变量仍会覆盖新目录的表

- **位置：** `runtime/src/host_main.c:117-152,326; runtime/src/caps.c:74-77`
- **影响：** 切程序触发重读帧率表，但若环境中已有 S2A_FPS_TABLE，新目录的帧率表会被覆盖。
- **建议修法：** 切程序时清除 S2A_FPS_TABLE，或按新目录重算后更新环境变量。

### KI-043 calloc 失败后空指针当对象使用

- **位置：** `runtime/src/svc_mem.c:1792; runtime/src/thread.c:2323-2324,597-603`
- **影响：** calloc 失败时返回 NULL，调用方未检查即继续访问，仅在内存耗尽时触发。
